# brain v0.5.1

Brain v0.5.1 is built on **beads 1.1.0-rc.1**, the same base as v0.5.0. It is
not a port to beads 1.3. `bd version` reports `1.1.0-rc.1+brain.0.5.1`. The
previous release is `brain/v0.5.0`; its notes are
[`v0.5.0.md`](v0.5.0.md) and are unchanged.

v0.5.1 is a small release on top of v0.5.0: two fixes, a new way to run brain
from a second machine, date-keyed ids, and review fixes. Nothing here changes
the unified database or its namespace model.

## What is new

### Run brain from another machine: `brain remote` and `brain host promote`

`brain remote set | unset | status | install | disconnect` makes a machine a
client of a brain host. With a host set in `~/.config/brain/remote.yaml`, the
whole command line (arguments, stdin, TTY, exit code) is forwarded over one
multiplexed ssh connection through the host's own store wrappers. No database
port is exposed. `install` writes marker-tagged wrappers for every store in the
host's registry and never replaces an unmarked file or writes `bd`.

`brain host promote` moves the host role between machines, and clients follow
the move on their own. The page covers failure and rollback.
Docs: [`../REMOTE.md`](../REMOTE.md), [`../HOST_PROMOTE.md`](../HOST_PROMOTE.md),
`../../../divergence/0034-brain-remote-client-mode.md`,
`../../../divergence/0035-brain-host-promote.md`.

### Date-keyed ids per store: `create.id-pattern`

A store with `create.id-pattern` set to `day`, `week`, `month`, `quarter` or
`year` holds one bead per period. `bd create` derives the id from today (in
America/Los_Angeles) or from `--date`, checks an explicit `--id` against the
pattern, and refuses a second bead for the same period, naming the existing
one. Week ids are the Sunday that starts the week; quarter ids look like
`<prefix>-YYYY-qN`. `--file` and `--graph` are refused in such stores; `--parent`
children and wisps are exempt.
Docs: [`../../CONFIG.md`](../../CONFIG.md).

### Cross-store dependency edges show up (#25)

In the unified database a dependency on another store's bead is an ordinary
edge. `dep list` (and `--json`), `brain related` and `show --json` resolve the
target, including legacy `external:<store>:<id>` values. A target with no row
is shown as unresolved (`(not found)`, `"unresolved": true`) instead of a blank
bead.
Docs: [`../../DEPENDENCIES.md`](../../DEPENDENCIES.md),
`../../../divergence/0017-dep-add-silent-orphan-cross-store.md`.

### Audit-event payloads are capped (#16)

String values in `events` rows are limited to `BEADS_EVENT_FIELD_LIMIT` bytes
(default 1024), and an append collapses the unchanged prefix, so append-heavy
notes stay linear instead of quadratic. One append to a 40 KB notes field wrote
80,504 bytes before and 415 after. This is on by default for every store, so a
single field over 1 KB is elided in its audit row (the full value stays in
`issues`). Set `BEADS_EVENT_FIELD_LIMIT=0` to restore full copies.
Docs: `../../../divergence/0033-event-payload-elision.md`,
[`../../../CHANGELOG.md`](../../../CHANGELOG.md).

### `transfer` reads the registry `brain stores` writes (#32)

`transfer` decoded stores as name to string and appended `.beads` to the path,
but `brain stores add` writes `{path, about}` entries whose path is already the
`.beads` directory. The reader now accepts both entry shapes and both path
shapes.
Docs: [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md) (A-9).

### Review fixes (#30)

- Outbox command subscribers get a wait delay, a killed process group and a
  scrubbed environment, so a stuck subscriber command cannot hang delivery.
- The guard hook wrapper now also covers claim operations.
- Hook process-ancestry detection handles `ps` and glob edge cases.
- The shared-backup destination check and the unify replay's row inserts are
  fixed.

Docs: [`../HOOKS.md`](../HOOKS.md), [`../event-outbox.md`](../event-outbox.md),
`../../../divergence/0034-review-fixes-hooks-outbox-backup.md`.

### README

The README describes brain as one unified database with a namespace per store,
and as a graph of data and task beads linked by dependencies (#26).

## Upgrading

- Same beads base as v0.5.0 (1.1.0-rc.1). Moving to beads 1.3 is separate,
  later work.
- The event payload cap (#16) is on by default. If you rely on full before and
  after copies in `events` rows, set `BEADS_EVENT_FIELD_LIMIT=0`.
- Remote client mode, host promotion and date-keyed ids are opt-in.
