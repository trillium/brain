# brain v0.5.0

Brain v0.5.0 is built on **beads 1.1.0-rc.1**. It is not a port to beads 1.3.
`bd version` reports `1.1.0-rc.1+brain.0.5.0`. The previous release is
`brain/v0.4.0` (2026-06-27).

This release turns the store federation into something that can run on one
shared database, and adds the machinery around it: conflict records, prefix
release, hooks, a durable event outbox, markdown edit-back and shared-database
backup. The full per-feature inventory is
[`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md). The picture-first version is
[`../BRAIN_OVER_BEADS.md`](../BRAIN_OVER_BEADS.md).

## What is new

### One unified database, many stores

`bd brain unify plan | build | verify` merges every per-store Dolt database
into one database (`brain_unified`) while each store stays a separate
namespace. Reads are scoped to the wrapper's namespace by default and `--wide`
reads across all stores. Minting without a store is refused, and every mint is
checked against namespace ownership. `bd brain stores create` now provisions a
namespace instead of a database when the server hosts the unified shape. The
build is verified by byte-exact content digests.
Docs: [`../MERGING_DATABASES.md`](../MERGING_DATABASES.md),
[`../../design/brain-single-database.md`](../../design/brain-single-database.md),
[`../../design/brain-cutover-runbook.md`](../../design/brain-cutover-runbook.md).

### Keeping a merged database current: `unify replay`

`bd brain unify replay` carries changes made in the source databases since the
build into the merged database. It works against a database a running server
hosts, takes a server-side lock so two replays cannot run at once, and retries
(up to 15 times, with jitter) when a concurrent write wins the commit. After a
repoint, the catch-up merges instead of reloading. `--include-database` and
`--rescue-orphans-from` recover databases and rows the build did not see.
`bd brain unify verify --reference live` is the acceptance test.
Docs: [`../MERGING_DATABASES.md`](../MERGING_DATABASES.md),
`../../../divergence/0027-brain-unify-replay.md`.

### Conflict beads

When the same id is held by several stores and the copies differ, unify no
longer picks a winner and drops the rest. Each differing copy is kept and a
conflict bead is filed for review. Identical copies are still reduced to one.
Docs: [`../MERGING_DATABASES.md`](../MERGING_DATABASES.md),
[`../../design/brain-collision-duplication-records.md`](../../design/brain-collision-duplication-records.md),
`../../../divergence/0028-brain-unify-conflict-beads.md`.

### Runtime prefix claims, release and history

`bd store-prefix add | list` claims a prefix for a store at run time.
`bd store-prefix release` gives a claim back and `bd store-prefix history`
shows the append-only ownership trail. A prefix that carries beads can never be
released; there is no override.
Docs: [`../PREFIX_RELEASE.md`](../PREFIX_RELEASE.md),
[`../../design/brain-prefix-release.md`](../../design/brain-prefix-release.md).

### Guard and observer hooks

Hooks are declared in `hooks.d`. A guard can refuse a write. An observer can
only watch it, and cannot write even with its environment scrubbed. Warnings
are routable. `bd hook list` shows what is declared.
Docs: [`../HOOKS.md`](../HOOKS.md),
`../../../divergence/0030-brain-hooks-guard-observer.md`.

### Durable event outbox

With `change-events.outbox.enabled`, each write's events become rows in the
store's own `event_outbox` table and are delivered to subscribers with
bounded-backoff retries until acknowledged. A subscriber being down delays an
event; it does not lose one. `bd outbox list` and the other `bd outbox` verbs
show and repair the backlog. Server-mode stores only.
Docs: [`../event-outbox.md`](../event-outbox.md),
`../../../divergence/0031-durable-event-outbox.md`.

### Markdown edit-back and mark-for-deletion

Opt in per store with `bd stores edit-back`. Edits to a rendered markdown file
are applied back to the bead. A file marked for deletion labels the bead
`marked-for-deletion` rather than deleting it. Cross-id slug overwrites are
refused, and the render root now follows the store's namespace.
Docs: [`../EDIT_BACK.md`](../EDIT_BACK.md),
`../../../divergence/0029-brain-markdown-editback.md`.

### Shared-database backup

When several stores share one database, `bd backup` backs the database up
once: one destination, one throttle, one lock.
Docs: `../../../divergence/0032-shared-database-backup.md`,
[`../../CLI_REFERENCE.md`](../../CLI_REFERENCE.md).

### Smaller additions

- `bd create --edit` (`-E`) composes the title and body in `$EDITOR`.
  [`../../CLI_REFERENCE.md`](../../CLI_REFERENCE.md)
- Ranked search that tokenizes multi-word queries, searches descriptions and
  comment bodies, and weights titles above bodies. `bd search --federated`
  walks every registered store. [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md)
- `bd stores doctor` probes each store the way an agent reaches it.
  [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md)
- Voice identifiers: issue JSON carries an additive kebab-case `name` next to
  `id`. [`../VOICE_IDENTIFIERS.md`](../VOICE_IDENTIFIERS.md)
- Version token `1.1.0-rc.1+brain.0.5.0`; `bd version --combined` prints only
  the token. [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md)
- Registry moved to `~/.config/brain` (the old `~/.config/pai` path is kept as a
  compatibility symlink), with `BRAIN_STORE` and `BRAIN_STORE_*` environment
  names. [`../../BRAIN_DEPAI_MIGRATION.md`](../../BRAIN_DEPAI_MIGRATION.md)
- Per-mutation `change-events.jsonl` lines, one per mutated bead id, and the
  `brain-emit` webhook wrapper. [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md)
- `beads-mcp` gains a project registry with a foreground/backlog resolver.
- The retired v0.3 ISA is archived at
  [`../archive/ISA-v03.md`](../archive/ISA-v03.md).
  The approved direction is [`../../../VISION.md`](../../../VISION.md).

## Upgrading

- The beads base is unchanged from v0.4.0's line: 1.1.0-rc.1. Moving to beads
  1.3 is separate, later work.
- Nothing requires the unified database. A federation of per-store databases
  keeps working. Read [`../MERGING_DATABASES.md`](../MERGING_DATABASES.md) and
  the cutover runbook before running `unify build`.
- The outbox, edit-back and hooks are opt-in.

## Known limits

- The outbox needs a server-mode store. With it enabled, an embedded store
  refuses every write by name.
- Prefix release does not cover claims made before the ownership trail
  existed; see [`../PREFIX_RELEASE.md`](../PREFIX_RELEASE.md).
- Open defects in the verb surface are listed under C-9 in
  [`../WHAT_BRAIN_ADDS.md`](../WHAT_BRAIN_ADDS.md).
